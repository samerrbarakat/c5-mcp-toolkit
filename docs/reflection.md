# Reflection

Maison Noisette already had five natural tools from C4 (menu search, policies, cake quotes, leads and feedback), so the hard part of this assignment was choosing three that actually depend on each other. I drew every line with one question: does this information change when someone places an order? Prices, allergens and opening hours never do, so they became resources that the agent reads at startup instead of tools. Stock does change, so `check_availability` became the Data tool, and it treats a "no" (a Monday, too little notice, too few left) as a normal answer rather than an error. `reserve_order`, the Action tool, does the opposite: if an order cannot be saved, it raises a clear error and saves nothing, and it checks the stock again itself instead of trusting whoever called it. The boundary I debated most was `plan_event_order`, because "plans and reserves" fails the "and" test. I kept it because combining the other two is exactly what an Orchestration tool is for, and because fitting a guest count, a budget, allergens and the remaining stock together is arithmetic that belongs in tested code, not in the model's reasoning. Running the check and the reservation in one call also means no other request to the server can take the stock in between.

Three tools were enough to show a real chain, but they are not the right number for a real bakery. The limit worked because the resources carried all the read-only facts, yet it left an obvious gap: a customer can place a pending order but cannot change or cancel it. The most useful lesson came from testing the agent rather than the server. When the menu reached the model as raw JSON, it listed only two of the seven items without nuts; formatting the same resource as one line per item fixed it, which showed me that how the host presents a resource matters as much as what the server returns. As next steps, I would add a tool to cancel orders, move the orders from a JSON file to SQLite so that several server processes can share them safely (each stdio client starts its own), serve the toolkit over HTTP so a website bot and a staff assistant could use the same server, and evaluate the agent on a fixed set of questions, the way I compared prompts in C4.
